# 02 - The output alphabet: table or rules

Status: **open**. Audit: "What converged", the render map bullet.

## The choice

`data/render/ipa.yaml` holds one row per feature tuple the model can produce.
A consonant key is `letter|geminate|emphatic|nasal`; a vowel key is
`quality|long|emphatic`. 99 rows, generated by `tools/build_render_map.py`,
71 reached over the full corpus by both scripts with default khilaf.

The design is deliberate and its stated benefit is real: a tuple with no row
raises `NotationError`, so an unrenderable sound is loud rather than silent.
The question is whether that benefit survives a schema where the row count is
not the product of the feature space.

## Why the row count is the problem

Gemination is one fact -- say the consonant twice -- written 28 times as
`bb`, `tt`, `θθ`. Emphasis is one fact written once per emphatic letter.
The file does not say what a feature *means*; it says what every combination
of features *spells*.

Consequences:

- Adding a letter is two rows minimum, more if it can be emphatic.
- Adding a feature doubles the file.
- A second notation (buckwalter, a teaching orthography, a mualem view) is a
  second 99-row generated file with the same redundancy.
- The generator exists because nobody would write 99 rows by hand, and a
  generated data file means the real source is the generator.

## Do not delete the 28 unreached rows

Reach count is not evidence of deadness. Some of the 28 are reachable only
under a non-default khilaf selection, and the khilaf catalogue is not complete
(see [06](06-seen-sad-khilaf.md)). Any pruning has to be justified by "the
model cannot produce this tuple", not by "the corpus did not produce it".

This is worth stating because three reviewers independently measured 71/99 and
two of them proposed deleting the remainder.

## Two shapes

### A. Semantic entries with overrides

Base consonants keyed by `CanonLetter`, then named overrides for the features
that change the token rather than repeat it:

- an emphatic override only where emphasis is not a suffix,
- a nasal override only where nasality is not a suffix,
- `geminate` as a documented composition rule, not 28 rows,
- `long_suffix` for vowels.

Around 52 entries, hand-writable, and `tools/build_render_map.py` is deleted
because there is nothing to generate.

The cost: the totality guarantee moves from "every tuple has a row" to "every
tuple resolves". That is a weaker statement unless the resolver is total by
construction, which means `render/alphabet.py` must be retyped on
`CanonLetter`, `Quality`, `NasalPlace` and `ReleaseKind` rather than on
strings, and a conformance check must enumerate the tuple space and assert
every member resolves. That check replaces the row count as the guarantee.

### B. Keep the table, generate it from a semantic source

The YAML stays as it is; the semantic entries become the generator's input.
Totality is unchanged and the redundancy moves out of the committed file.

Cheaper and lower risk. But the committed data file is then a build artefact,
which the package has otherwise avoided, and a second notation still means a
second generated file.

## What to audit before deciding

1. **Which of the 99 rows are not a composition.** If a token is not
   base + suffix, it is a genuine entry and shape A must have a row for it.
   The emphatic consonants and the nasals are the candidates; establish the
   exact set.
2. **Whether `NasalPlace` and `ReleaseKind` are in the tuple space at all.**
   Both appear in `model/performance.py`; establish whether the render map
   keys on them today or whether they reach the token by another path.
3. **Whether a second notation is actually wanted.** If the answer is no,
   shape B is sufficient and this document closes as "no change". The mualem
   spec in `docs/` is the reason to think the answer is yes.

## Acceptance

- No generated data file in `quranic_phonemizer/data/`.
- `render/alphabet.py` types its keys on model enums.
- A conformance check enumerates the producible tuple space and asserts every
  member resolves to a token, replacing row-count totality.
- Adding a letter to `CanonLetter` is one entry.
